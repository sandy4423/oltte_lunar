# 만두앱 /admin 「전달완료」가 캠페인 주문(떡국만두)을 제대로 처리하게

## 목표
만두집 컴퓨터의 `www.olttefood.com/admin` 에서 떡국만두(캠페인) 주문에 「전달완료」를
눌렀을 때, 장부앱 카운터의 「수령 완료」와 **같은 결과**가 되게 한다.

## 제약
- 운영 중인 주문앱. push = Vercel 배포. 되돌릴 수 있게.
- 전골 주문(캠페인 아님) 흐름은 **한 글자도 안 바뀌어야** 한다.
- 장부앱 레포는 **읽기만**. 관리자 인증 · `next.config.mjs` · `constants.ts` 변경 금지.
- 실제 수령 처리 · 문자 발송을 **실행하지 않는다**. 운영 주문이 수령 대기로 살아 있다.
- `git add/commit/push`, `npm install` 금지 (이 작업 범위 밖).

## 현재 상태 (조사로 확인된 사실)

### 어긋나는 지점
| | 만두앱 「전달완료」 | 장부앱 카운터 「수령 완료」 |
|---|---|---|
| 쓰는 값 | `orders.status='DELIVERED'` + `updated_at` | `orders.picked_up_at` + `updated_at` |
| status | DELIVERED 로 바꿈 | **PAID 그대로 둠** |
| 문자 | `createDeliveredSMS` (픽업해 가주셔서 감사합니다) | `createPickupDoneSMS` (수령이 완료되었습니다) |

- 만두앱 `src` 전체에 `picked_up_at` 0건 (읽지도 쓰지도 않음)
- 장부앱 카운터의 「입금완료」 집합 = `['PAID','LATE_DEPOSIT']` → `DELIVERED` 는 빠진다
  → 만두앱에서 누르면 장부앱이 그 주문을 「입금대기」로 보고, 수령 버튼도 409 로 막힌다

### DB 실측 (2026-09-22)
- `orders.campaign_id`, `orders.picked_up_at` 존재
- 떡국만두 캠페인 `tteokguk26` = `d4fd20ec-da99-43cc-b0e2-c11ac610d83c`, store = 만두(1호점)
- `review_events` 행은 **`fresh` 하나뿐** → 떡국만두 수령완료 문자엔 리뷰 링크가 **붙지 않는다**
  - 장부앱 `lib/review/links.ts` 의 `REVIEW_PAGE_SLUGS = new Set(['fresh'])` 라
    tteokguk26 은 **앞으로도** 링크가 안 붙는다 (리뷰 화면 자체가 fresh 에만 있음)
- `campaign_products` (tteokguk26) 3개 전부 `is_addon=false` → 단위는 전부 「팩」
- 떡국만두 주문 중 `picked_up_at` 이 찍힌 것 **0건** (아직 아무도 수령 처리 안 함)
- `campaign_order_details.ship_name` 은 tteokguk26 전부 null (매장 수령)

### 장부앱 카운터가 하는 일 (api/fresh/admin/pickup) — 그대로 맞춰야 할 규칙
1. 택배 주문(`campaign_order_details.ship_name` 있음)은 **수령 처리하지 않는다** (409)
2. `status` 가 PAID·LATE_DEPOSIT 이 아니면 막는다 (409)
3. 이미 `picked_up_at` 이 있으면 덮어쓰지 않고 409 + 원래 시각을 돌려준다
4. UPDATE 에 `.is('picked_up_at', null)` + `.in('status', PAID)` 를 걸어 동시 클릭 방어
5. 그 다음 수령완료 문자 (실패해도 수령 처리는 되돌리지 않는다)

## 결정 사항

### ① 캠페인 주문은 `status` 를 건드리지 않고 `picked_up_at` 만 찍는다
`DELIVERED` 는 「입금됨」을 뜻하지 않는다. 바꾸면 장부앱 입금·정산 판정이 흔들린다.

### ② 문자 — 장부앱 문안을 그대로 맞춘다 (2026-09-22 결정)
선택지:
- (a) 만두앱 기존 픽업 문자를 그대로 보낸다 → **기각**.
  문안이 다르다(같은 캠페인 손님끼리 다른 문자를 받는다). 게다가 그 문자는
  `customers.name` 으로 손님을 부르는데, 캠페인 주문의 `customers.name` 은
  깨진 값이 섞여 있다(장부앱 주석의 실측). 장부앱은 `depositor_name` 을 쓴다.
- (b) 캠페인 주문엔 문자를 안 보낸다 → **기각**.
  같은 버튼인데 어느 화면에서 눌렀냐에 따라 손님이 영수증 문자를 받거나 못 받는다.
  사장님이 그 차이를 매번 기억해야 한다.
- (c) **장부앱 `createPickupDoneSMS` 문안을 그대로 만두앱에 옮긴다 → 채택**
  - 떡국만두는 리뷰 링크가 원래 안 붙으므로(위 실측) 문안이 **완전히 고정**이다
    → 두 앱이 보내는 문자가 byte 단위로 같다. 노브가 없어서 드리프트 여지가 작다
  - 아는 캠페인(slug)만 문자를 보낸다. 모르는 캠페인은 **문자 없이 수령 처리만** 하고
    그 사실을 화면에 알린다 (모르는 가게 이름·단위를 추측해 보내지 않는다)

### ③ 수령한 것 눈으로 구분
- `picked_up_at` 이 있으면 목록·상세에 **「✅ 수령완료 M/d HH:mm」 배지**
- 상태 필터에 「수령완료」 / 「수령 안 함」 두 항목 추가
