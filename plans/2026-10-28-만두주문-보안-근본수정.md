## 근본 수정 (다시 열기 전에 전부 끝낼 것, 한 단계씩 배포·확인)
원칙: 브라우저는 DB 를 직접 만지지 않는다. 모든 읽기·쓰기는 서버 경로(service role)에서,
서버가 「이 사람이 이 주문의 주인인가」를 확인한 뒤에만.

- R1 주문 만들기 서버로: 새 POST /api/orders/create (service role).
  body 는 {sku, qty}[]·이름·전화·수령일/시간·마케팅 동의만. **가격·합계·할인은 서버가
  PRODUCTS + src/lib/pricing.ts 로 다시 계산**(브라우저 값 무시). status 는 서버가 CREATED 로 고정.
  손님 찾기/만들기(전화번호)도 서버에서. useOrderSubmit.ts 의 직접 insert 3곳을 fetch 하나로.
  응답은 {orderId, amount, accessToken}.
- R2 주문 조회 서버로 + 주인 확인: useOrderPolling.ts → /api/orders/detail.
  detail 은 orderId 만으로 열리면 안 됨 → R1 의 accessToken(주문별 임의값, DB 에는 해시만)
  을 같이 받아야 응답. 돌려주는 열은 화면에 쓰는 것만(toss_secret·toss_payment_key·
  cash_receipt_key·refund_account_* 제외).
- R3 결제 승인 서버끼리 검증: /api/payments/confirm 은 이미 토스 confirm API 를 부름 →
  비교 금액을 **R1 에서 서버가 계산해 저장한 금액**으로. 가상계좌 발급도 같은 금액.
- R4 웹훅 비밀값: toss_secret 을 아무도 못 읽게(이번 DB 잠금으로 공개 읽기는 막힘).
  추가로 웹훅이 PAID 로 바꾸기 전에 토스 API(GET /v1/payments/{paymentKey}, 비밀 키)로
  status=DONE·금액 일치를 직접 확인. secret 비교만으로 결제 완료 처리하지 않는다.
  웹훅 본문 console.log 제거(secret 이 로그에 남음).
- R5 관리 화면: /admin 새 주문 알림(useNewOrderAlert.ts)의 공개 키 실시간 구독·order_items 직접 읽기를
  /api/admin/orders 주기 조회(10~15초)로 교체. 관리자 로그인(adminAuth)은 서버 쿠키 검증인지
  다시 확인하고 /admin/* 화면과 /api/admin/* 전부 사장님·직원 인증 뒤에만.
  realtime 발행에서 orders 빼기: alter publication supabase_realtime drop table public.orders;
  (장부앱이 orders 를 구독하지 않는지 먼저 확인)
- R6 /my-orders 내 주문: 문자 인증 후 서버가 그 전화번호 주문만 돌려주는지 확인(현재 service role).
- 각 단계 확인: 시험 주문(카드·가상계좌) → 완료 화면, 개발자 도구 Network 에
  /rest/v1/orders|customers|order_items 호출이 0건, 공개 키로 세 표 SELECT 0행.
- 다시 열기: src/lib/ordering.ts ORDERING_OPEN=true → 커밋·푸시 → / 에서 주문 화면 확인.

### 2단계(DB 잠금) 되돌리기 SQL — 보안 구멍이 다시 열리니 긴급할 때만
```sql
begin;
create policy anon_select_customers on public.customers for select to anon using (true);
create policy authenticated_select_customers on public.customers for select to authenticated using (true);
create policy anon_insert_customers on public.customers for insert to anon with check (true);
create policy authenticated_insert_customers on public.customers for insert to authenticated with check (true);
create policy anon_select_orders on public.orders for select to anon using (true);
create policy authenticated_select_orders on public.orders for select to authenticated using (true);
create policy anon_insert_orders on public.orders for insert to anon with check (true);
create policy authenticated_insert_orders on public.orders for insert to authenticated with check (true);
create policy anon_select_order_items on public.order_items for select to anon using (true);
create policy authenticated_select_order_items on public.order_items for select to authenticated using (true);
create policy anon_insert_order_items on public.order_items for insert to anon with check (true);
create policy authenticated_insert_order_items on public.order_items for insert to authenticated with check (true);
grant update, delete on public.orders, public.customers, public.order_items to authenticated;
commit;
```
(바꾸기 전 anon 에는 update/delete 권한이 원래 없었다. 원본: 세션 scratchpad policies-before-step3-20261028.json)
